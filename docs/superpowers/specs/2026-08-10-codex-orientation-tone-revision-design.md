## Goal

Revise the audience-facing copy in `slide_deck/AIagentic_workflow_orientation_tutorial_ICISE_2026August10.html` so it reads as a restrained scientific orientation rather than promotional product messaging.

## Scope

This is a copy-only revision. Preserve:

## Editorial treatment

Replace large claims and motivational slogans with descriptive teaching language. Titles should state what the slide explains or demonstrates, without implying that the tool transforms research practice or guarantees an outcome.

Representative changes:

| Current treatment | Revised treatment |
| --- | --- |
| “Leave with a workflow, not a feature list.” | “What this session covers” |
| “Chat answers. An agent acts.” | “What distinguishes an agentic workflow” |
| “The loop is simple. The work can be deep.” | “Most tasks follow the same working loop” |
| “Codex can work across the whole research environment.” | “The working context can include code, tools, and documents” |
| “Useful autonomy has explicit boundaries.” | “Sandboxing and approvals define the operating boundaries” |
| “A skill turns a good method into a repeatable one.” | “Skills package reusable instructions and checks” |
| “Give the agent a question with an observable finish line.” | “State the task and how the result will be checked” |
| “The result is not a tour. It is a working model.” | “An onboarding pass should produce a working model of the repository” |
| “The finish line is evidence, not a generated file.” | “The verification script checks all six independent entries” |
| “A strong prompt names the finish line.” | “A practical prompt includes five pieces” |
| “Pick one real task. Put verification in the prompt.” | “Try the method on one research task” |

Short body copy will receive the same treatment where it overstates scope or outcome.
